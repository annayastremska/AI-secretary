# eval/retrieval — набори для пошуку по нормативці

Набори Андрія, приїхали з main 01.09.2026. Формат описаний у шапці кожного
файла.

| Файл | Що це | Хто читає |
|---|---|---|
| `truth_units.tsv` | правильна одиниця для питання: документ + підрядок, який у ній мусить бути. Перевірка механічна, без оцінювача | `ab_embedding_models.py`, `measure_rerank_lift.py` |
| `truth_units_v2.tsv` | друга редакція тієї самої істини | `ab_fusion_weights.py`, `metrics_report.py`, `diagnose_source_failures.py` |
| `truth_units_terms.tsv` | дзеркало `_v2`: ті самі одиниці, але питання вживають ТЕРМІНОЛОГІЮ документа. Потрібне, бо в `_v2` питання перефразовані, і лексична гілка систематично в невигідному становищі | `metrics_report.py`, `diagnose_source_failures.py` |
| `abstain_set.tsv` | калібрування ВІДМОВИ; клас — факт про корпус, не оцінка видачі | `measure_abstain_signal.py`, `measure_gate_criterion.py` |
| `abstain_v2.tsv` | друга редакція набору відмови | `metrics_report.py` |
| `probe_positive.txt` | питання, відповіді на які в корпусі Є: ловить хибну відмову | — (ручний прогін) |
| `adversarial_questions.txt` | питання, на яких пошук ламається. Розмітки немає: це не калібрування, а перевірка «чи не стало гірше» | — (ручний прогін) |
| `slang.txt` | розмовні запити | `expand_slang.py` |
| `stress10.txt` | десять стрес-тестів, кожен — окремий режим відмови | — (ручний прогін) |
| `probe5.txt` | п'ять питань для перевірки цитування моделлю | `quote_with_llm_test.py` |

Три файли без читача — це нормально: їх прогонять руками. Але саме тому вони
легко застарівають, і перед використанням треба глянути дату останньої зміни.
