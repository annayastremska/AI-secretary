# storage

Один інтерфейс (`base.py`), дві реалізації з ОДНАКОВОЮ схемою ключів
`documents/<domain>/<id>.md`, тому перехід "ноут → MinIO клієнта" — це зміна
`storage.backend` у конфізі, а не переписування пайплайна, і вже наявний
`data/output` переливається в бакет як є.

- `local_store.py` — файлова система; індекс хешів `index/processed.jsonl`
  для дедуплікації. **Робочий, перевірений.**
- `minio_store.py` — MinIO; дедуплікація через маркер-об'єкт `index/<hash>`
  (один `stat`, без листингу бакета). **Не перевірено на живому сервері.**
- `postgres_writer.py` — запис у БД за `db/schema.sql`; дедуплікація через
  `UNIQUE(file_hash)`, тобто гарантія тримається й при паралельних процесах.
  **Не перевірено на живій базі.**

Ототожнення осіб навмисно НЕ автоматичне: новий документ дає чернетковий
`subject`, об'єднання підтверджує людина (див. коментарі в `db/schema.sql`).
