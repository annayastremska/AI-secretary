# storage

Локальне файлове сховище результатів (`local_store.py`) — єдиний бекенд.
Зовнішнє сховище (MinIO) і база даних **поза межами цієї частини роботи**.

- Ключі: `documents/<domain>/<id>.md`; `unresolved` — завжди окремою текою,
  щоб черга ручного розгляду лишалась одним місцем, куди дивиться людина, а
  не розсипалась по доменних теках через вгаданий грубий домен.
- Дедуплікація: append-only індекс `index/processed.jsonl` (хеш вмісту → ключ).
  Не база, але достатньо, щоб той самий документ, завантажений двічі під
  різними іменами, не дав двох фактів.
- Вміст запису — YAML-шапка з `subject`, `facts`, `field_provenance`; у тілі
  лише розпізнаний текст.

Схема ключів пласка й передбачувана, тому `data/output` можна буде перелити
в будь-яке зовнішнє сховище пізніше, коли за це візьметься відповідна
частина команди.
