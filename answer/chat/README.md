# Чат — вікно відповіді (тестовий стенд)

Чат, який відповідає на питання про людей і документи частини. Усі дані
вигадані, за травень 2026. Дороги А («підрахунок») і Б («нормативка») з
`README.md` кореня репо тут обидві живуть на SQLite-стенді, поки `db/` не
готовий на Postgres.

## Запуск

```bash
pip install -r answer/chat/requirements.txt
python answer/chat/seed.py   # збирає stand.sqlite з answer/chat/data/
python answer/chat/app.py    # відкриє http://127.0.0.1:7861
```

На Mac можна замість трьох команд двічі клацнути `start-mac.command`.

**Модель необов'язкова.** Маршрутизацію робить локальна MamayLM через
Ollama (`ollama serve`, модель `mamaylm-4b`). Якщо Ollama не запущена, чат
працює на правилах і чесно каже про це окремим блоком у відповіді —
цифри й цитати від цього не змінюються, бо їх дає база, не модель.
Переозначити: `OLLAMA_MODEL` / `OLLAMA_HOST` у `.env` поруч або в оточенні.

## Як влаштована відповідь

Текст **кожної** відповіді формує код, не модель. Модель робить лише два
структуровані виклики — маршрут і параметри — тому вигадати цифру чи цитату
вона фізично не може.

Формат: спершу цифра або конкретика, потім пояснення; джерело — у згортці
під відповіддю (правило ТЗ #52 «біля відповіді видно джерело» лишається
виконаним, але джерело не заступає саму відповідь). Дефект даних — порожні
поля, суперечливі дати — це і є відповідь, тому він іде першим рядком, а не
приміткою.

Візуальний шар відокремлений: `theme.css` тримає всі токени на `:root`, а
`app.py` не має inline-стилів. `render_reply()` розкладає готовий текст по
блоках (попередження, інформація, помилка) — самі формулювання при цьому не
змінюються.

## Перемикання на Postgres

Один рядок у `app.py`:

```python
import db  # noqa: E402
```

міняється на:

```python
import db_postgres as db  # noqa: E402
```

коли `db/db_postgres.py` готовий і проходить `verify.py` (копію із заміненим
імпортом).
