# Цикл покращення якості й швидкості пайплайна

Складено 15.08.2026 на замовлення Анни: «підняти якість і швидкість де це
можливо — тестувати, виправляти, перевіряти». ВЛК-схема відкладена рішенням
Анни; MVP-скоуп — відпустки, відрядження, нормативні.

Відрізняється від рев'ю 14.08 (`docs/review-plan-2026-08-14.md`) метою:
рев'ю шукало ПОМИЛКИ, цей цикл шукає РЕЗЕРВИ якості й швидкості. Тому перша
фаза — не пошук знахідок, а вимірювання, де болить: без карти «покращення»
перетворюється на випадкові правки.

## Фази

**Фаза 0 — Профілювальник** (один агент, правок НЕ робить).
Повна карта болю з цифрами:
- час по стадіях на документ: інжест, OCR, ідентифікація, кожне LLM-поле
  окремо, морфологія, збірка запису;
- якість по кожному полю на всіх корпусах, включно з фото;
- профіль пам'яті обох процесів (llama_mem_sampler уже є);
- невиміряні місця (що взагалі не міряється — теж біль).
Вихід: `docs/improvement-2026-08-15/p0-profile.md` — беклог вузьких місць,
відсортований за «ціна × частота», кожен пункт із цифрою.

**Фаза 1 — Дослідники** (по одному на кластер беклогу, OCR-кластери
послідовно). Відомі кластери вже два:
- витік пам'яті llama-server (27 МБ/1000 токенів; веб-ресьорч відомих issue
  llama.cpp/Surya + локальний експеримент із версіями/параметрами);
- якість і швидкість на РЕАЛЬНОМУ фото (23.5 хв при зайнятій RAM; половина
  полів через LLM з довірою 0.6; препроцесинг, параметри Surya).
Профілювальник додасть решту. Вихід кожного: пропозиція з ПРОГНОЗОВАНИМ
виграшем у цифрі та ціною. «Є така технологія» без заміру на нашій машині
(i5-1235U, 15.6 ГБ, без GPU) не приймається.

**Фаза 2 — Виконавець** (один, послідовно). По одній пропозиції:
замір ДО → правка → замір ПІСЛЯ. Правка без відтворюваного виграшу —
відкат, чесно записаний як «спробували, не дало». Коміт на правку.

**Фаза 3 — Верифікатор.** Незалежно перепрогонить заміри виконавця.
Покращення, яке не відтворюється, — не покращення. Вихід: вердикт по
кожній правці + оновлення `docs/known-weak-spots.md`.

**Цикл:** після Фази 3 — рішення: ще раунд чи стоп. Стеля — 2-3 раунди;
далі майже напевно полірування. Зупинка «далі дорожче, ніж варте» — чесний
результат, не поразка.

## Правила (виведені з досвіду 14.08, обов'язкові для всіх агентів)

1. Заморожений тест-сет (LEAVE-005/013/016, TRIP-003/009/014): на них не
   дивляться під час правки; прогін — лише як фінальна цифра.
2. Інвентар хардкоду не росте: правка, що додає в `.py` знання про
   конкретну форму, відхиляється навіть якщо піднімає цифру. Знання про
   форму — у схему/довідник.
3. Еталони (`data/eval/synthetic-2026-05/`, `holdout/*.expected.json`)
   недоторкані. Власна копія гомогліфів у приладі — навмисна.
4. Один OCR/LLM-прогін за раз. Замір швидкості дійсний лише з записаною
   вільною RAM на старті.
5. Діагноз — тільки з рядком доказу (лог, відтворення, цифра). За 14.08
   три переконливі діагнози виявились хибними.
6. Запис на диск по ходу, не в кінці (ліміт сесії вбиває мовчунів).
7. Фонових моніторів не ставити; довгі процеси — синхронно.
8. Агенти не комітять, коли працюють паралельно; послідовний виконавець —
   комітить по одній правці.
9. Все локально: жодних нових мережевих залежностей; перевірку
   SURYA_INFERENCE_URL не послаблювати.
10. Персональні значення з реальних документів не потрапляють ні в docs,
    ні в коміти, ні в звіти (інцидент 15.08 — один раз досить).

## Критерії приймання раунду

1. Кожна прийнята правка має відтворений верифікатором виграш.
2. Корпуси не просіли: leave docx/pdf 224/224, deployment docx/pdf
   183/183, фото 166/167 і 152/155, тестів ≥206.
3. Кожна відкинута пропозиція записана з причиною (щоб не досліджували
   двічі).
4. Беклог після раунду оновлений: що закрито, що лишилось, що додалось.
