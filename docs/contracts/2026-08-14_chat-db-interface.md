_Складено 2026-08-11, уточнено того ж дня. Проєкт курсу KSE, епік corp-study#84 «Чат»._

Це домовленість між двома ділянками: **чат** (Ден) і **база** (Андрій).

Чат ніколи не пише SQL. Він зве функції з файлу `db.py`. Що всередині цих
функцій — SQLite на тестовому стенді, Postgres у бойовій версії — чат не знає
і знати не повинен.

**Домовились про це — і далі працюємо паралельно, не заважаючи одне одному.**
У п'ятницю міняється один рядок імпорту.

## Три таблиці

### `people` — хто служить

Джерело: `unit_roster.csv` з генератора синтетичних документів (corp-study#86).
Кількість людей — скільки є в реєстрі, число не фіксуємо. З 37 колонок
реєстру беремо шість.

| Колонка | Тип | Приклад |
|---|---|---|
| `service_id` | text, ключ | `UNIT-0001` |
| `full_name` | text | `Гавриш Адам Станіславович` |
| `rank` | text | `сержант` |
| `position_title` | text | `старшина роти` |
| `subdivision` | text | `2-га механізована рота` |
| `phone` | text | `+380 02 654-23-51` |

### `absences` — хто поза частиною

Один рядок = один документ. Джерело: генератор, документи за травень 2026.
Кількість не фіксуємо — набір поповнюється.

| Колонка | Тип | Приклад | Нащо |
|---|---|---|---|
| `doc_number` | text | `№145` | не унікальний: буває два документи з одним номером |
| `doc_date` | date | `2026-05-04` | дата видачі |
| `doc_type` | text | `відпустка` / `відрядження` | |
| `service_id` | text, може бути порожнім | `UNIT-0017` | порожньо = людини немає в реєстрі |
| `person_name_raw` | text | ПІБ як написано в документі | щоб ловити розбіжність із реєстром |
| `date_from` | date, може бути порожнім | `2026-05-10` | |
| `date_to` | date, може бути порожнім | `2026-05-24` | |
| `reason` | text | `щорічна основна відпустка за 2026 рік` | |
| `place` | text | `м. Полтава` | |
| `status` | text | `чинний` / `скасований` / `чернетка` | |
| `superseded_by` | text, може бути порожнім | `№151` | номер документа, який цей скасував |
| `source_file` | text | `leave_007.pdf` | звідки взято |

Зіпсовані документи лежать як є: з порожніми полями, з `date_to` раніше
`date_from`. Чат має це побачити і назвати, а не виправити мовчки.

### `reference_docs` — внутрішні документи частини

Один рядок = **один розділ документа**, не весь документ. Інакше чат цитує
три сторінки замість абзацу.

| Колонка | Тип | Приклад |
|---|---|---|
| `doc_title` | text | `Порядок оформлення відпустки в частині` |
| `section_number` | text | `2.3` |
| `section_title` | text | `Строки подання рапорту` |
| `text` | text | текст розділу |
| `source_note` | text | `внутрішній документ частини, ред. 2026-04` |

`source_note` обов'язковий — правило ТЗ (corp-study#52): біля відповіді завжди
видно джерело.

## Функції, які зве чат

Сім штук. Більше на демо не потрібно.

```python
find_people(subdivision=None, name=None) -> list[dict]
```
Люди з реєстру. Обидва фільтри необов'язкові, `name` — часткове співпадіння.

```python
absences_on_date(date, subdivision=None, doc_type=None) -> list[dict]
```
Хто поза частиною в цей день. Тільки `status = чинний`.
Документ із порожньою `date_from` або `date_to` сюди не потрапляє
(немає дат — немає підстави вважати людину відсутньою в цей день);
такий документ видно через `document_by_number` і `absences_for_person`.
Питання №1 і №4 із переліку замовника.

```python
returning_on_date(date, subdivision=None) -> list[dict]
```
У кого `date_to` = ця дата. Тільки `status = чинний` — скасований документ
нікого не повертає. Питання №2.

```python
absences_for_person(name_or_service_id, only_active=True) -> list[dict]
```
Усі документи на людину. `only_active=False` повертає і скасовані —
потрібно для питання «чи була ще якась відпустка». Питання №5.
Як шукається людина: точний збіг за `service_id`, АБО часткове співпадіння
з ПІБ у документі (`person_name_raw`), АБО часткове співпадіння з ПІБ
у реєстрі (`full_name`).

```python
document_by_number(doc_number) -> list[dict]
```
Повертає **список**, не один запис: буває два документи з тим самим номером.
Чат сам вирішує, який чинний.

```python
count_absent_by_subdivision(date) -> list[dict]
```
Рядки `{subdivision, absent, total}`. Питання №4, рядок добової довідки.

```python
search_reference(query, limit=3) -> list[dict]
```
Пошук по `reference_docs`. Повертає розділи з полем `score`.
На стенді — простий пошук за словами. У бойовій версії — Postgres FTS.

## Правила, однакові для обох реалізацій

1. **Функція повертає дані, не текст для людини.** Формулює відповідь чат.
2. **Нічого не знайшли — порожній список.** Не виняток, не `None`.
3. **Дати скрізь ISO:** `YYYY-MM-DD`, рядком. На вході і на виході.
4. **Кожен рядок про документ несе джерело:** `doc_number` + `source_file`,
   або `doc_title` + `section_number`. Без цього чат не має що показати
   людині. Виняток — підсумкові рядки (`count_absent_by_subdivision`) і
   рядки реєстру (`find_people`): це рахунок по всій базі, окремого
   документа-джерела в них немає.
5. **Порожнє поле лишається порожнім.** Функція не підставляє нічого замість
   незаповненого звання чи дати — це саме те, що чат має назвати.
6. **Функція не вирішує, який документ чинний, коли їх два.** Віддає обидва.

## Що з цього НЕ покривається

Два питання замовника не працюють, і причина не в коді.

| Питання | Чого бракує |
|---|---|
| №3 «Хто ще не повернувся станом на `[дата]`?» | у документах немає відмітки про фактичне повернення |
| №6 «Чи можна відпустити ще одного з `[підрозділ]`?» | немає норми: скільки людей одночасно дозволено відпустити |

Обидва — питання до замовника, не до бази. На демо їх у сценарій не беремо,
на пряме запитання відповідаємо чесно.

| Хто | Що |
