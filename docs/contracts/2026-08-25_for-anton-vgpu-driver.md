# Антону: потрібно перевстановити гостьовий драйвер vGPU (наша помилка)

_25.08.2026, від Ані (капстоун №21, AI-секретар). Коротко: **ми знесли
гостьовий драйвер vGPU на віртуалці 185.9.41.1**. Обчислення поки працюють,
але після перезавантаження карта не підніметься. Просимо поставити драйвер
назад — своїми силами ми його не відновимо, бо це ліцензійне ПО NVIDIA, якого
ні в репозиторіях, ні на диску вже немає._

## Що ми зробили і чим

Нам потрібно було зібрати `llama-server` з підтримкою CUDA (готового
складання під Linux у релізах llama.cpp немає), для цього потрібен `nvcc`.
Поставили системний CUDA-toolkit:

    sudo apt-get install -y nvidia-cuda-toolkit

Ця установка **видалила** пакет `nvidia-linux-grid-580` (580.126.09) і
поставила натомість загальні `libnvidia-compute-610`,
`nvidia-kernel-common-610`, `nvidia-firmware-610`:

    /var/log/apt/history.log
    Start-Date: 2026-08-25  08:29:36
    Commandline: apt-get install -y -qq nvidia-cuda-toolkit
    Requested-By: ubuntu (1000)
    Remove: nvidia-linux-grid-580:amd64 (580.126.09)

Ми робили пробний прогін (`apt-get -s`) перед установкою, але подивились на
нього неправильно: обрізали вивід кінцем, а рядки `Remv` стоять на початку
плану. Тобто apt попередив — попередження не побачили. Це наша помилка, не
збіг обставин.

## Що ми вже відкатили самі

- прибрали **все, що ставили**: `nvidia-cuda-toolkit` + 231 супутній пакет
  (`autoremove --purge`), `nvcc` більше немає;
- драйверні пакети 610 **не чіпали навмисно**: зараз саме їхній `libcuda`
  тримає робочі обчислення, і прибрати їх означало б зламати карту негайно;
- ці три пакети **заморозили** (`apt-mark hold`), щоб автоматичні оновлення
  більше нічого тут не рухали;
- перевірили після відкату: карта рахує.

## Чому не відновили драйвер самі

- `apt-cache policy nvidia-linux-grid-580` → `Candidate: none` — у
  репозиторіях пакета немає (ставився з локального `.deb`);
- `.deb`/`.run` немає на диску: шукали по всій кореневій ФС (`find / -xdev`),
  інших змонтованих ФС із даними немає;
- бібліотеки 580 знайшлись лише всередині шару контейнерного образу
  (`580.95.05`, CUDA-compat) — для модуля ядра не годяться;
- **загальний драйвер з архіву Ubuntu ставити не стали.** Там є
  `nvidia-driver-580-server` 580.173.02, але це інша версія, у гостьовій
  системі vGPU він може не отримати ліцензію від гіпервізора, а перевірити
  можна лише перезавантаженням — тобто саме тією дією, після якої втратимо
  й те, що зараз працює. Вирішили не робити цього без вас.

## Прохання

**Поставити назад гостьовий драйвер vGPU 580.126.09** — той самий пакет, яким
ставили віртуалку. `/etc/nvidia/gridd.conf` на місці, тому ліцензія має
підхопитись сама. Якщо перед установкою потрібно прибрати наші пакети 610 —
приберіть, вони заморожені `hold`, знімається так:

    sudo apt-mark unhold libnvidia-compute-610 nvidia-kernel-common-610 \
                         nvidia-firmware-610-610.43.02

Якщо простіше перестворити віртуалку зі снапшота — теж підійде, але тоді
скажіть заздалегідь: у нас на ній лежить робота (див. нижче), треба буде
зняти копію.
