Складено 14.08.2026, після переносу в KSE-репо. Це знімок стану: перелік усього
відкритого з `docs/known-weak-spots.md` та `docs/open-questions.md`, зведений в
одне місце, і план агентів під нього. Нічого з плану ще не виконувалось.

Джерело кожного рядка — розділ у `known-weak-spots.md`, тому дублювати опис тут
не треба: у таблицях лише що це, чого коштує і хто може закрити.

## Частина 2. План агентів

### Спільні правила для всіх агентів

**Повноваження, які має кожен:**
- читати весь репозиторій;
- запускати `python run_pipeline.py` і `python -m eval.evaluate`;
- писати результат у свій розділ `docs/`;
- один коміт із докладним повідомленням українською.

**Заборони, однакові для всіх:**
1. **Не редагувати `data/eval/synthetic-2026-05/`** — це відповіді. Не збігається
   результат — змінюй правило порівняння або код, не відповіді.
2. **Не послаблювати `.gitignore`** — виняток для файлів документів рівно один.
3. **Не чіпати `eval/field-mapping.yaml` і `eval/evaluate.py`**, якщо агент не
   призначений саме на прилад. Прилад незалежний від того, що міряє; зокрема
   ВЛАСНА копія таблиці гомогліфів в оцінювачі — навмисна, прибирати не можна.
4. **Не звітувати «виправлено» без заміру ДО і ПІСЛЯ** на тому самому наборі.
5. Кожен агент, що торкається шляху з LLM або OCR, **мусить фактично запустити
   модель**. Аспект, який неможливо перевірити без моделі, не вважається
   перевіреним.
6. Не запускати два OCR-прогони одночасно: швидкість визначається вільною RAM
   (B3), паралельні прогони псують і швидкість, і сам замір.

### Агент 1 — Сітка безпеки: тести й прилад

**Мандат:** закрити E1-E2, щоб решта плану мала на що спиратися.

| | |
|---|---|
| Закриває | E1, E2 |
| Може писати | `requirements-dev.txt`, `eval/tests/**`, `eval/README.md` |
| Не може | змінювати `pipeline/**`; змінювати логіку `evaluate.py` (лише запускати) |
| Мусить запустити | `pytest eval/tests` до й після |
| Результат | усі тести проходять; у `docs/` записано, які падали й чому |

Обов'язково додати регресійні тести на дві щойно заміряні речі:
самозцілення OCR (мертвий сервер → перезапуск) і `400 grammar` (живий сервер →
перезапуску НЕ буде, документ чесно `unresolved`). Обидві поведінки заміряні
14.08 і зараз не мають тесту.

### Агент 2 — `місце` і label-екстракція на OCR

**Мандат:** закрити A1, наскільки дозволяє геометрія; підняти A2; корінь — A3.

| | |
|---|---|
| Закриває | A1, A3, частково A2 |
| Може писати | `pipeline/extraction/**`, геометрію в `pipeline/ingestion/**`, блок `extraction` у `pipeline/schemas/*.yaml` |
| Не може | торкатися приладу й еталона; вимикати LLM «щоб швидше» |
| Мусить запустити | Surya на 16 фото відпускних + docx-базу тим самим приладом |
| Результат | `місце` > 0; жодне поле не просіло проти docx-базової лінії |

Ключова умова: **порівняння з docx-базою обов'язкове**. Правка, яка підняла фото
й опустила docx, — не поліпшення, а обмін одного на інше, і в звіті це має бути
видно окремими колонками.

### Агент 3 — Причина накопичувального збою

**Мандат:** закрити B1 — встановити, ЩО накопичується. Не лікувати симптом.

| | |
|---|---|
| Закриває | B1; після нього стає можливим B2 |
| Може писати | `pipeline/ocr/**`, діагностичний скрипт у `pipeline/scripts/` |
| Не може | змінювати екстракцію; розширювати умову перезапуску до встановлення причини |
| Мусить запустити | пакет 16 фото з логом на кожен документ: вільна RAM, RSS обох процесів, `/health`, кількість блоків, час |
| Результат | у `docs/` названо, що саме вичерпується, з цифрами по документах — або чесно «не встановлено, ось що виключено» |

Уже виключено: сам кадр (той самий LEAVE-011 першим у пакеті дає 9/11) і
«стан після перезапуску» (у прогоні w4 після перезапуску вісім документів
пройшли нормально). Не приписувати причину без рядка з логу — це вже двічі
виявлялось хибним.

### Агент 4 — Порожній бланк і друковані рядки

**Мандат:** A5, A7, A6.

| | |
|---|---|
| Закриває | A5, A7, A6 |
| Може писати | `pipeline/extraction/extract.py`, `pipeline/schemas/*.yaml`, тести в `eval/tests/` |
| Не може | чіпати еталон; вводити «глобальний денилист фраз» без оголошення в схемі |
| Мусить запустити | порожній шаблон + повний корпус docx (регресія: жодне заповнене поле не втрачене) |
| Результат | на порожньому бланку — нуль полів зі значеннями `matched` |

Рішення, яке треба прийняти в межах цього агента: перевіряти кандидата проти
тексту ПОРОЖНЬОГО шаблону (сильніше, універсальніше — але вимагає, щоб шаблон
лежав поруч зі схемою) або оголошувати друковані фрази в схемі (слабше, зате без
нових залежностей). Агент має обґрунтувати вибір, а не зробити мовчки.

### Агент 5 — Універсальність: дослідження, не код

**Мандат:** C1, C2 — з оцінкою, чи наш підхід узагалі конкурентний.

| | |
|---|---|
| Закриває | пропозицію по C1, C2; оцінку C3, C4 |
| Може писати | `docs/architecture/**`; у коді — лише попередження валідатора схем |
| Не може | переписувати екстракцію; вводити нову залежність без заміру на нашому CPU |
| Мусить зробити | deep research: як 2026 року розбирають багаторядкові таблиці й документи з кількома суб'єктами; порівняти з нашим підходом честно, включно з варіантом «наш гірший» |
| Результат | пропозиція з цифрами вартості на нашій машині (i5-1235U, 15.6 ГБ), а не «є така технологія» |

Обмеження, які не можна забути в оцінці: усе крутиться на CPU без GPU; 2-5 хв на
документ — прийнятно; вихід мусить лишатися сумісним із контрактом БД
(`docs/contracts/2026-08-11_database-handoff.md`).

### Порядок і чому саме такий

1. **Агент 1** — перший і окремо. Без тестів решта правок іде без сітки.
2. **Агент 2 і Агент 3** — після нього, але **не одночасно**: обидва вантажать
   Surya, а швидкість визначається вільною RAM (B3). Спершу 3 (причина), бо його
   висновок може змінити те, як 2 міряє.
3. **Агент 4** — паралельно до OCR-агентів: він детермінований, моделі не
   потребує, файли не перетинаються.
4. **Агент 5** — паралельно будь-коли: тільки читання й `docs/`.
5. **Агент 6** — паралельно будь-коли: код не торкається.

### Що НЕ входить у план і чому

- **A8 (оцінка стоїть на синтетиці)** — потрібні реальні бланки, а вони не
  можуть покидати частину. Це не задача агента, а домовленість про те, як
  провести замір локально, і рішення Анни.
- **C3, C5, D1-D3** — заблоковані контрактом БД або даними, яких у нас немає.
  Агент 6 лише формулює.
- **E3, E4** — рішення Анни: чи повертати перевірку на креденшели й коли ротувати
  ключ. Код тут ні до чого.
- **B4, D6** — реальні, але недосяжні або без наслідків. Записані, щоб не
  «знаходились» удруге.
