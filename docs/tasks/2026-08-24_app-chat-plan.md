# План робіт: апка + чат до демо

Складено 24.08.2026 з переліку `2026-08-24_app-chat-worklist.md` після його
валідації. Це робочий план для команди: етапи, задачі, критерії готовності.

Зафіксовані рішення Ані: чат — проти справжньої бази; модель — MamayLM v2
**27B** (та сама, що в пайплайні); демо-гілка — `anya-pipeline`; штатка — задача
Андрія; харнес — **готовий із доробкою**, безкоштовний і без лімітів.

## 0. Що змінено проти переліку при валідації

Перелік перевірено на суперечності з новішими рішеннями й на повноту. Зміни —
явно, щоб їх було видно:

**Виправлені суперечності:**

1. Перелік радив *не* брати бібліотеку `semantic-router` («тридцять рядків
   свого коду»). Це суперечить рішенню Ані «взяти готове» і результату
   дослідження (`docs/research/2026-08-24_chat-harness-recommendation.md`):
   бібліотека MIT, без лімітів, має локальний режим із `LlamaCppLLM` —
   **беремо її**, не пишемо своє.
2. Перелік фіксував encoder `snowflake-arctic-embed-l-v2.0` як вирішений.
   Українська в його картці прямо не підтверджена — **вибір encoder-а
   робиться заміром** на нашому тест-сеті (кандидати: `multilingual-e5-base`,
   `bge-m3`, `snowflake-arctic`). Один encoder на два завдання: роутер чата й
   нормативний пошук.
3. «Стан діалогу в Postgres» (патерн LangGraph) — **прибрано як зайве** для
   демо: слоти живуть у сесії (функції Андрія вже так працюють), а
   довговічність дає журнал відповідей.

**Додано (цього в переліку не було):**

4. **Порядок: правка `validity_model` — ДО завантаження бази.** Лоадер створює
   рядок виміру при першому факті; якщо завантажити 198 записів до правки, три
   виміри назавжди отримають неправильну модель чинності, і перезавантаження
   записів цього не виправить.
5. **Деплой на сервер як окрема задача**: порт 80 → ззовні 7302, Basic-auth,
   димова перевірка **із зовнішнього браузера**. У переліку були функції апки,
   але не її розгортання.
6. **Ваги encoder-а на сервер заздалегідь** (`~/shared/models`), робота
   офлайн — сервер не має ходити в HuggingFace під час демо.
7. **Один екземпляр 27B на процес.** Апка вантажить модель для пайплайна
   (subprocess) і чат тримає свою резидентну — дві одночасні інференції 27B на
   CPU неприпустимі. Потрібен лок/черга на використання моделі.
8. **Індикатор «думаю» на фолбеку**: виклик 27B — це ~43 с, і користувач мусить
   бачити прогрес, а не завислий екран (те саме для фото — 47 с).
9. **Мінімум нормативного пошуку без Андрія**: гібридний пошук вимагає таблиці
   `document_chunks` з векторами, якої немає і яку ніхто не наповнював. Але FTS
   із українським конфігом уже в наших міграціях, а 41 акт лежить у
   `documents.text_content`. P0 — пошук по `text_content` через `ts_rank`;
   гібрид із векторами — після демо.
10. **Префікси `query:`/`passage:` для e5** — без них якість encoder-а падає;
    дрібниця, яка губиться, якщо не записати.
11. **«Зараз» перевірено, а не вирішено навмання**: демо-дані покривають
    серпень–вересень 2026, демо — до 31.08, отже дефолт «станом на сьогодні»
    влучає у вікно даних. Дату у відповіді показуємо завжди.

**Прибрано в «після демо» (P2):** середня/максимальна тривалість, топ
напрямків, історія змін особи, «всі документи про особу», «коли документ
завантажено», оновлення `how-it-works.html`, гібридний пошук із векторами,
Rasa CALM, Open WebUI.

## 2. Перевірка плану проти обмежень проєкту

| обмеження | як план його виконує |
|---|---|
| у git жодних реальних даних; на сервер лише синтетика | план не додає нових джерел даних; база наповнюється тільки з `data/output-demo/` (синтетика) |
| чернетка ≠ факт | 5.1: чернетки не в підрахунку І видимі у відповіді |
| цифру дає база, модель не пише SQL | шаблони параметризовані (етап 2), модель лише обирає шаблон і слоти під GBNF (4.1) — вигадане число неможливе за побудовою |
| відмова краща за вигадку | 3.3 (фолбек замість впевнено-неправильного маршруту), 5.3, 7.4 |
| зони власності (`db/`, `airflow/` — Андрій) | міграції виконуємо, не правимо; єдина правка — 0.1, один рядок, позначена в коміті; штатка не робиться (заблокований шаблон + чесна відмова) |
| модель зафіксована (27B) | економія лише на кількості викликів (роутер + один виклик), не на моделі |
| без GPU (ліцензія) | усі цільові часи заміряні/розраховані на CPU; якщо GPU повернеться — стає швидше, план не змінюється |
| сервер до 31.08 | усе в git; на сервері лише runtime (база, ваги, журнал) |
| критерії до прогону, не після | 7.2 стоїть перед 7.3 явно |
| безкоштовно, без лімітів | semantic-router MIT; encoder-и MIT/Apache; жодних ключів |
| українська всюди | харнес мови не торкається; encoder обирається заміром на українських питаннях; текст відповіді пише наш код |

## 3. Ризики

1. **Роутер не добере 90% на наших питаннях** → фолбек ловить решту коштом
   43 с; поріг можна опустити (більше фолбеків = повільніше, але не
   неправильно). Це деградація швидкості, не правдивості.
2. **27B на CPU дає >43 с під навантаженням** (паралельний upload) → лок 4.4
   серіалізує; на демо не запускати upload і питання одночасно.
3. **Андрій повернеться з іншою думкою по схемі** → ми нічого в схемі не
   міняли; єдиний дотик — 0.1, обґрунтований і однорядковий.
4. **GPU оживе** (ліцензія/перезавантаження) → нічого не переробляється,
   просто швидше.
5. **`semantic-router` (версія 0.x) розчарує в локальному режимі** → заміна на
   Haystack-роутер або ~30 рядків `sentence-transformers` коштує день: каталог,
   приклади й тест-сет від бібліотеки не залежать (запасний план — research,
   розд. 2.7).

## 4. Поза планом (сказати вголос, не закривати)

- цитата на рівні документа, не пункту (нарізки немає; `ts_headline`-фрагмент
  розглянуто й **не додано** — рішення Ані 24.08);
- синтез із кількох документів — не дозволяє конструкція, в обмін закритий
  prompt injection (позиція, не недоробка);
- підрозділи — до штатки Андрія;
- гібридний векторний пошук, Rasa CALM, Open WebUI — після демо;
- P2-шаблони: середня/макс тривалість, топ напрямків, історія змін особи.
