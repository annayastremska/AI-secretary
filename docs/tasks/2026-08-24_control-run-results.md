## 4. Чому фото не обробились — GPU без ліцензії

Це головна причина, чому прогін неповний, і вона не в коді.

```
nvidia-smi -q:  License Status : Unlicensed
                Product Brand : NVIDIA Virtual Compute Server

journalctl -u nvidia-gridd:
  22.08 11:30  GPU features and performance are restricted
  23.08 11:10  GPU features and performance are fully restricted
```

Віртуалці **ніколи не видавали ліцензію vGPU** — вона працювала на пільговому
періоді. Прогони 22–23.08 встигли пройти в «обмеженому» режимі; після
переходу в «повністю обмежений» CUDA-обчислення недоступні:

- `torch.zeros(1).cuda()` → `CUDA error: operation not supported`;
- `llama_cpp.Llama(...)` падає з `SIGABRT` у `ggml_backend_cuda_device_get_memory`
  **незалежно від `n_gpu_layers`** — CUDA-бекенд реєструється й у CPU-режимі.

**Обхід, яким пройшов цей прогін:** `CUDA_VISIBLE_DEVICES=` — llama.cpp не бачить
GPU й працює на CPU. Заміряно: **43 с на один виклик моделі** проти секунд на
GPU. Терпимо саме тому, що на впізнаному бланку модель не викликається зовсім
(заміряно 24.08): на всьому наборі це кілька викликів.

**Чого обхід не рятує:** OCR. Surya на NVIDIA піднімає vllm у docker, тобто
теж потребує CUDA. Тому чотири фото не обробились узагалі.

**Що потрібно:** client configuration token (`.tok`) з NVIDIA License System від
тих, хто видавав віртуалку, у `/etc/nvidia/ClientConfigToken/`, і
`systemctl restart nvidia-gridd`. Зараз цієї папки не існує, а в
`/etc/nvidia/gridd.conf` адреса сервера порожня.

**Цифри по фото від 23.08 лишаються чинними** — вони заміряні тоді, коли GPU ще
працював: три звичайні кадри 44/44, DEMO-10 (навмисно гірший) 5/14, `посада` 1/2.

## 5. Побічний висновок, вартий окремої згадки

Учора падали рівно ті документи, у яких є прогалина, і причина виявилась не
випадковою: **прогалина — єдине місце, де взагалі викликається модель.** На
впізнаному бланку детермінований шлях покриває все, а порожні слоти доведені,
тому фолбеку немає за побудовою.

Тобто «прогін із моделлю» на наших docx-корпусах нічого про модель не доводив
би — її там не викликають. Саме тому LLM-шлях закритий тестами з **макетом**
моделі (`eval/tests/test_llm_path.py`), а не прогоном: заземлення, пропуск
моделі на доведено-порожньому слоті й гілки збою тепер міряються щодня й
відтворювано.
