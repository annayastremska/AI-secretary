## 4. GPU без ліцензії

Це причина, чому прогін ішов на процесорі. Фото спершу не обробились саме
через неї — але не лише через неї: другу половину причини (нашу) і те, як фото
все-таки обробились, див. розд. 7.

```
nvidia-smi -q:  License Status : Unlicensed
                Product Brand : NVIDIA Virtual Compute Server

journalctl -u nvidia-gridd:
  22.08 11:30  GPU features and performance are restricted
  23.08 11:10  GPU features and performance are fully restricted
```

Віртуалці **ніколи не видавали ліцензію vGPU** — вона працювала на пільговому
періоді. Прогони 22–23.08 встигли пройти в «обмеженому» режимі; після
переходу в «повністю обмежений» CUDA-обчислення недоступні:

- `torch.zeros(1).cuda()` → `CUDA error: operation not supported`;
- `llama_cpp.Llama(...)` падає з `SIGABRT` у `ggml_backend_cuda_device_get_memory`
  **незалежно від `n_gpu_layers`** — CUDA-бекенд реєструється й у CPU-режимі.

**Обхід, яким пройшов цей прогін:** `CUDA_VISIBLE_DEVICES=` — llama.cpp не бачить
GPU й працює на CPU. Заміряно: **43 с на один виклик моделі** проти секунд на
GPU. Терпимо саме тому, що на впізнаному бланку модель не викликається зовсім
(заміряно 24.08): на всьому наборі це кілька викликів.

**Що спершу здавалось нерятівним:** OCR. Surya на NVIDIA піднімає vllm у
docker, тобто теж потребує CUDA, і чотири фото виходили `unresolved`. Виявилось,
що це неправда: у surya є другий бекенд (`llamacpp`), який працює на CPU, а
автовизначення його не обирало. Розд. 7.

**Що потрібно:** client configuration token (`.tok`) з NVIDIA License System від
тих, хто видавав віртуалку, у `/etc/nvidia/ClientConfigToken/`, і
`systemctl restart nvidia-gridd`. Зараз цієї папки не існує, а в
`/etc/nvidia/gridd.conf` адреса сервера порожня.

**Заміри по фото є свіжі, на CPU** — розд. 7.2. Цифри від 23.08 (на GPU)
лишаються чинними як порівняння: три звичайні кадри 44/44, DEMO-10 5/14.

## 5. Побічний висновок, вартий окремої згадки

Учора падали рівно ті документи, у яких є прогалина, і причина виявилась не
випадковою: **прогалина — єдине місце, де взагалі викликається модель.** На
впізнаному бланку детермінований шлях покриває все, а порожні слоти доведені,
тому фолбеку немає за побудовою.

Тобто «прогін із моделлю» на наших docx-корпусах нічого про модель не доводив
би — її там не викликають. Саме тому LLM-шлях закритий тестами з **макетом**
моделі (`eval/tests/test_llm_path.py`), а не прогоном: заземлення, пропуск
моделі на доведено-порожньому слоті й гілки збою тепер міряються щодня й
відтворювано.

## 7. Доповнення: фото таки обробились — і половина причини була наша

Дописано 24.08 після того, як прогін уже був зафіксований як неповний.

### 7.1. Друга причина, крім ліцензії

`surya/inference/__init__.py:_autodetect_backend()` обирає бекенд так:

```python
if _has_nvidia_gpu():      # nvidia-smi -L, і все
    return "vllm"
return "llamacpp"
```

Тобто рішення спирається на **наявність** карти, а не на її працездатність. При
неліцензованому vGPU карта в `nvidia-smi` лишається — тому surya щоразу
вибирала vllm, той не піднімався, і кожне фото коштувало **600 с таймауту** й
виходило `unresolved`.

**Ми ніколи не закріплювали бекенд явно** — і це наша частина провини. Тепер
його оголошує конфіг (`ocr.inference_backend`), а `null` лишає попереднє
автовизначення, щоб на робочих машинах не змінилось нічого.

### 7.3. Побічний баг, який виявив невдалий прогін

Запис про помилку OCR отримав у `reason` **багаторядкове** повідомлення
(`SpawnError` тягнув за собою лог чужого процесу), і frontmatter став
**невалідним YAML** — `yaml.safe_load` падав із `found unexpected end of
stream`.

Ціна була б не «негарний файл»: завантажувач бази читає саме frontmatter, тобто
**один зіпсований запис валив би завантаження всієї пачки** — і рівно тоді, коли
щось уже пішло не так. Виправлено (`one_line_reason`), три тести, у тому числі
на YAML-обіг.

### 7.4. Підсумковий стан виходу

- **198 записів**, `unresolved` = 0, 176 `confirmed` + 22 `needs_review`;
- **усі 198 читаються як валідний YAML** (перевірено окремо після 7.3);
- **426 текстових значень** `matched` — усі дослівно в документах, 0 винятків;
- дублікатів немає, записів без вхідного файлу немає, `superseded/` прибрано:
  у демо-виході лежить рівно один повний прогін;

Ліцензія vGPU лишається питанням до адміністраторів, але **демо вона більше не
блокує**.
