# Конвеєр агентів для роботи над проєктом

Цей файл фіксує стандартну схему запуску агентів, щоб кожен раз вона була послідовною, а не вигаданою заново. Мета — уникнути повторення ситуації, коли твердження зі слабкого джерела (студентський конспект про АСКОД) було подано як факт без належної перевірки.

Оркестратор (Claude) сам не є окремим агентом — він запускає нижченаведених агентів, передає результати між ними та керує циклами.

## 1. Research agent

- **Вхід:** конкретне дослідницьке питання + релевантні файли контексту проєкту.
- **Дія:** паралельний пошук по кількох кутах питання (orchestrator-worker всередині).
- **Вихід:** список тверджень, кожне — з джерелом (URL) і коротким описом. Без власного вердикту "це правда" — оцінку робить наступний агент.

## 2. Validation / fact-check agent

- **Вхід:** твердження від Research agent.
- **Ранжування джерел:**
  - Рівень 1: офіційна документація, першоджерело, урядовий/вендорський сайт.
  - Рівень 2: визнані технічні видання, рецензовані публікації.
  - Рівень 3: блоги компаній.
  - Рівень 4 (не приймається як факт): форуми, студентські конспекти, анонімний контент, неавторитетні агрегатори.
- **Правило підтвердження:** твердження визнається підтвердженим лише за наявності мінімум 2 незалежних джерел рівня 1-2. Джерело рівня 4 ніколи не подається як факт — тільки як "непідтверджено, джерело: X".
- **Цикл зі зворотним зв'язком:** якщо доказів бракує або є суперечність — Validation agent повертає Research agent конкретний запит (наприклад, "знайти підтвердження/спростування твердження Y"). Ліміт — 2 раунди повторного пошуку. Якщо після цього питання не закрито — явно позначається "нез'ясовано, ескалація до Анни", без здогадок.

## 3. Ideas / recommendations agent

- **Вхід:** лише твердження, що пройшли Validation (підтверджені або явно позначені як непідтверджені — ніколи мовчки прийняті).
- **Дія:** формулює архітектурні пропозиції, ідеї, рекомендації на основі цих тверджень.
- **Обмеження:** не додає власних нових фактичних тверджень від себе без проходження через Research → Validation.

## 4. Compliance check agent

- **Вхід:** пропозиції від Ideas/recommendations agent.
- **Дія:** звіряє кожну пропозицію з security-constraints.md і collaboration-rules.md (чи торкається реальних даних, чи вимагає хмари для продакшн-рішення, чи порушує інші зафіксовані обмеження).
- **Цикл зі зворотним зв'язком:** якщо пропозиція порушує обмеження — повертає Ideas agent конкретну причину відмови, той переформульовує. Ліміт — 2 раунди, далі — ескалація до Анни.

## Загальний потік

Research → Validation (цикл з Research) → Ideas/Recommendations → Compliance check (цикл з Ideas) → фінальний результат подається Анні, з чітким розділенням: що підтверджено, що не підтверджено, що не пройшло перевірку на відповідність обмеженням, що ескальовано як нез'ясоване.

## Контроль витрат

Ліміти на кількість раундів (2) в обох циклах введені свідомо — проєкт без бюджету, працюємо на Claude Team, тому цикли не мають тривати нескінченно.
