# db — сховище

Власник: Андрій.

Два сховища, різні задачі:

| Що | Чим | Що зберігає |
|---|---|---|
| Файли | тека `data/originals/` | самі документи (скани, фото, docx) |
| Факти | Postgres | витягнуті поля у структурованому вигляді |

Оригінали лежать у звичайній теці. MinIO стояв тут до 20.08.2026 — прибрали,
бо від сховища потрібно лише покласти файл і видалити його через 30 днів, а
адмініструвати S3-сумісний сервіс у підрозділі нікому. Наслідок, який треба
тримати в голові: 30-денне видалення більше не робить сховище саме — його
робить `scripts/purge_expired_originals.py`, і він мусить запускатись за
розкладом.

## Що тут лежить

- `migrations/` — 16 Alembic-міграцій: реєстр документів/об'єктів/фактів,
  функції `resolve_or_create_object`/`next_document_for_processing`,
  `dimensions.validity_model` (ranged / current_state / permanent_event),
  Ukrainian FTS (Hunspell), `unit` у `object_kinds`, `new_person` у
  `review_queue.queue_type`.
- `init/` — bootstrap користувачів/бази при першому старті контейнера.
- `seeds/` — генератор синтетичного реєстру особового складу.
- `tsearch_data/` — Hunspell-словник української (`brown-uk/dict_uk` через
  `wooorm/dictionaries`, GPLv3 — на радар юриста) для FTS.
- `scripts/load_ai_secretary_output.py` — CLI-завантажувач виводу пайплайна
  Ані (`data/output/documents/**/*.md`) у цю БД.
- `scripts/purge_expired_originals.py` — видаляє оригінали, чий строк вийшов
  (`documents.expires_at`). Замінює ILM-правило MinIO; має `--dry-run`.
- `scripts/start-docker-safe.ps1` — обхід відомого бага Docker Desktop на
  Windows (docker/desktop-feedback#460): стартує стек, автоматично чистить
  застряглі AF_UNIX socket-файли після неохайного вимкнення.

Решта `scripts/` — разові заміри й діагностики (`measure_*`, `diagnose_*`,
`ab_*`, `compare_*`): вони лишились як запис того, ЩО і ЯК було зміряно, і для
роботи бази не потрібні. Три виняток з них -- не разові, і без них базу з нуля
не піднімеш:

- `scripts/load_unit_roster.py` — завантаження штатки (реєстр особового
  складу). Потрібен при піднятті бази з нуля: без штатки резолвер осіб не має
  до чого прив'язувати факти.
- `scripts/set_normative_validity.py` — проставляє чинність нормативним
  документам. Пошук фільтрує по `documents.validity = 'current'`, тому до
  цього запуску нормативна дорога не віддає НІЧОГО.
- `scripts/detect_overlap_conflicts.py` — детектор перекриттів (одна особа у
  двох чинних діапазонних станах одночасно). Не діагностика: його число живить
  метрику «конфлікти станів» на вітрині (комміт `dc7f22a`).

Запуск локально: `cp .env.example .env` (заповнити значення) →
`docker compose up -d` → `alembic upgrade head`.

### Перший запуск на НОВОМУ сервері -- два обов'язкові кроки

Стенд, на якому все мірялось, помер 31.08.2026, тому наскрізь ці дві речі
ніхто не перевіряв. Порядок має значення.

**1. Починати з НОРМАТИВНОГО питання, не з кадрового.** Нормативна дорога
єдина, яку мердж 01.09 міг зламати тихо: назви таблиць одиниць переїхали зі
схеми в повні імена (`document_units` замість `andriy_test.document_units`), і
розбіжність тут виглядає не як падіння, а як «нормативка нічого не знаходить».
Кадрове питання цю поломку не покаже -- воно йде іншою дорогою.

**2. Переміряти метрики й порівняти з коммітом.** Знімок лежить у git:

    python db/scripts/metrics_report.py --out data/eval/andriy-metrics-new.json
    git diff --no-index data/eval/andriy-metrics.json data/eval/andriy-metrics-new.json

Очікування: **різниці немає**. Причина, чому це варто перевірити саме тепер:
01.09 розширення запиту синонімами вимкнено за замовчуванням (див. комміт
«Синоніми вимкнено за замовчуванням»), а `SU.lexical()` без аргументів
викликається з 13 вимірювальних скриптів. За заміром 27.08 наскрізь воно не
змінювало жодної відповіді -- але це ПЕРЕДБАЧЕННЯ, і на новому сервері воно
вперше стає фактом. Зрушити, якщо передбачення хибне, можуть три метрики:
«нормативних питань закрито з першого разу» (13/15), «дослівні цитати з
документів» (37/40) і «відмова на питання поза корпусом» (7/10).

Логіка мапінгу виводу Ані на цю схему — `airflow/plugins/ai_secretary_loader.py`
(той самий код, що й у `airflow/dags/load_ai_secretary_output_dag.py`, щоб не
дублювати між CLI і Airflow). Контракт із пайплайном — `docs/contracts/2026-08-11_database-handoff.md`.

## Дампи в git не їдуть

Схема потрібна в репо, дані — ні. Дамп може містити витягнуті реальні дані,
тому `dumps/`, `*.dump`, `backup*.sql` заблоковані в `.gitignore`.

База мусить розрізняти підтверджений факт і чернетку. Відповідь користувачу

результату.
